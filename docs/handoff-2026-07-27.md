## Deploy rules — read before doing anything

- **NEVER `git push` without Karl typing the literal phrase "Deploy Live"** (or
  an unmistakable equivalent). Committing freely is fine and expected.
- Deploy is `git push origin main` — this branch must be merged first.
- **`prisma.config.ts` points `datasource.url` at PRODUCTION** (`DIRECT_URL`).
  A bare `prisma db push` / `prisma migrate` / `migrate diff --from-migrations`
  writes to prod. Always `npm run db:push:dev`, and hand-write migrations.
- `db:push:dev` writes **no migration file**, and prod deploys with
  `migrate deploy`. A pushed-but-unmigrated column silently does not exist in
  production. This already bit us once (`20260726170000_trainer_schedule_view_prefs`).

### Prod checklist when it does deploy

## Traps that have already cost hours

- **e2e specs share ONE seeded database and one trainer.** A spec that mutates
  shared state (a persisted preference, an invoice's description) must restore
  it in `afterAll`, or it silently breaks a *later* spec. `scheduleView` made
  previously-independent specs order-dependent this way.
- **Paid add-ons are never seeded.** A spec for a gated page then reads the
  Add-ons redirect instead of the page — which looks exactly like a tenancy
  leak (a cross-tenant test reading 200 instead of 404). Two false alarms so
  far. Seed a `BillingItem` + `TrainerAddon` (see `global-setup.ts`).
- **A `vi.mock` factory replaces a module wholesale.** Omit a constant the code
  reads at module scope and the whole test file dies at import, before a single
  test runs.
- **Specs can silently SKIP** when the seed has nothing to act on — a green
  suite is not proof they ran.
- **Background agents die with their session.** A session limit killed six
  mid-edit and left ~90 half-written files. Commit early.
- **`git commit` takes the whole INDEX, not just the paths you added.** With
  several agents working at once, `git add <your-path>` then `git commit` will
  sweep up anything a colleague had already staged. This happened twice tonight:
  the multi-ticket-enrolment feature (schema, migration, lib, route, UI, three
  test files) is committed under `4649a1d "feat(forms): one editor for every
  kind of form…"`, and the memberships rename is buried in the WIP checkpoint
  `5c9a7b3`. Nothing was lost, but neither is findable by its message. Use
  `git commit -- <path> [<path>…]`, which commits ONLY those paths regardless
  of what else is staged.
- **Don't `rm -rf .next` or `npm run build`** while Karl's dev server is up on
  port **7777** — it breaks his running app.
- `next build` typechecks; `vitest` only transpiles. A type error can hide from
  the unit suite and still fail CI.

## Bugs fixed tonight that were live or would have been

Worth knowing these existed, in case related reports come in:

- **Offering images destroyed by unrelated edits** — the PATCH route wrote
  `imageUrl: imageUrl ?? null` unconditionally, so an omitted key became null.
  Renaming an offering wiped its image.
- **Ticketed events undercharged on client self-booking** — quoted the package
  price, not the ticket price ($45 for a $200 ticket).
- **`/sessions/[id]` 404'd every group-class session** — 588 of 898. The query
  filtered `clientId: { not: null }`, but group sessions have a null client by
  design (attendance is per-enrollee).
- **No phone screen had a heading element** — `h1` only rendered on desktop.
- **The mobile tab bar's safe-area inset wasn't reserved** — the last row of
  every phone screen sat under the bar on a notched iPhone. Only reproduces on
  real hardware; emulators report a 0px inset.
- **Saving any one-off event failed** with a flat "Failed to save" — an empty
  starter ticket row failed validation.
